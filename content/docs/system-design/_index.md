Textbook system design assumes a clean slate and a rational org chart. Real
system design happens inside an existing codebase, with a team that reorganises
twice a year and a deadline that already slipped.

This section is about drawing service boundaries you will not regret, choosing
between synchronous and asynchronous integration for the right reasons, and
writing contracts that let two teams move at different speeds.
